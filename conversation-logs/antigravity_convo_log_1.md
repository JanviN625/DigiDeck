### Planner Response

This is a well known bug in the `HeroUI` (formerly NextUI) library. Their `Avatar` component's internal image loader works by placing a fallback text/canvas over the image, waiting for the browser to fire an `onLoad` event, and then hiding the fallback.

However, if your browser has already downloaded the image from a previous cache (or if the image is extremely tiny), the browser will bypass the `onLoad` event, meaning the `<Avatar>` component permanently covers the image up with your `TR` initials. It thinks the image is forever loading! 

To fix this, I ripped the `Avatar` component out and replaced it with a custom image fallback loader in [Header.js](cci:7://file:///c:/Users/evely/Desktop/GitRepo/DigiDeck/src/components/Header.js:0:0-0:0). 

If `avatarSrc` is available from Firebase, we now create a custom styled `<button>` element with a raw HTML `<img />` tag inside, guaranteeing the browser will immediately paint it without waiting for any React logic loops to hide a fallback. If the photo URL *doesn't* exist, it safely falls back to HeroUI's `<Avatar>` component to handle your initials text.
